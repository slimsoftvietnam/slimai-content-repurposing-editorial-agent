# Quality review, research, visuals, and duplicates

## Evidence and claim review

Before delivery, check important factual statements against the supplied source or cited research. Keep a source note for claims added during external research. Flag contradictions, uncertain causal claims, missing context, stale figures, and legal/medical/financial statements requiring expert review. Do not make up statistics, testimonials, product features, or case studies. A source document is evidence of what that document says, not independent proof that every claim is true.

## SEO review

- State the query, likely intent, audience, and the useful answer the post provides.
- Review relevant current search results if browsing is available; use official or reliable references for factual claims. Do not report a keyword-volume estimate unless a suitable data source actually provides it.
- Check title/meta title, concise meta description, readable slug, answer-first opening, descriptive headings, topic coverage, examples/steps, caveats, useful links, and natural keyword use.
- Make the article substantial enough to solve the reader's problem. Do not use arbitrary word-count padding, repetitive keyword variants, or unsupported “rank on page one” promises.
- Clearly distinguish research-based additions from the source-derived narrative.

## Visual creation and asset provenance

- For each requested blog, provide a cover plus distinct in-article illustrations for the article's major concepts, process steps, or sections. Choose the count from the article structure: include enough to make the article visually complete, avoid filler/repeated images, and do not assume one illustration can stand in for the whole article. Map every image to its blog and placement (cover or section) in the calendar/workbook.
- When the user supplies a visual reference, capture its relevant style traits and map each asset to a specific calendar item. Ask for a new direction only if the reference is ambiguous and the difference materially affects the result. If the user rejects a generated style or says to stop, halt that asset type immediately, discard it from the handoff, and continue independent work without generating substitutes of the same type.
- Use the available image-generation skill for original visuals when appropriate. When the user wants text in an image, ask the image model to render the supplied short title/labels as part of the image; check Vietnamese spelling and regenerate a misspelled result. Keep the actual output in the project deliverables folder, use the proper channel dimensions after checking current platform guidance, and describe what the image represents. Do not invent charts or numeric claims in an illustration.
- For sourced images, record creator/source URL, license or usage terms, and required attribution alongside the deliverable. Check terms at the time of use; “found online” does not mean reusable.
- Examples of primary media references: [Unsplash API documentation](https://unsplash.com/documentation) and [Pexels API documentation](https://www.pexels.com/api/documentation/). Follow their current terms and attribution/API requirements.
- Do not make private Drive files public to enable insertion into a Doc. Google Docs API inline images have URI accessibility requirements; use the connected Docs integration/UI or a local DOCX route if a safe private workflow is unavailable. See [Google Docs API image insertion](https://developers.google.com/workspace/docs/api/how-tos/images).

## Duplicate and originality screening

- Compare new drafts with the other rows in the current calendar and any supplied/present archive that can be accessed. Run exact-match and near-match screening on meaningful passages, not just titles or topic overlap.
- Report the compared scope and likely overlaps, with file/row identifiers and short matching snippets. Suggest rewrites where the wording or structure is too similar.
- Similar topics are not necessarily duplicate copy. A similarity check is a drafting aid and is not legal plagiarism clearance or a guarantee against platform/content matching systems.
- If no archive is available, state that only the current batch was compared.

## Final handoff checklist

- Source claims and researched additions are distinguishable and traceable.
- Brand voice profile state (draft/approved), channel distinctions, SEO fields, and CTAs are checked.
- Image files exist, fit the intended channel, and have provenance/license details when sourced externally.
- Duplicate scope and flagged overlaps are reported.
- Calendar is valid, each row has complete copy, all dates are explicit or blank/proposed, and status changes match evidence.
